Three approaches to the "good pal" chat upgrade

All three deliver: inline charts (A+B), local model routing, data-sharing setting, better visuals. They differ in scope and order.

A

Layered (recommended)

Three separate implementation phases, each shippable on its own:

  1. Phase 1 — Visual refresh: new message bubble design, better typography, markdown polish, cleaner input area
  2. Phase 2 — Viz-in-chat: AI can emit chart configs inline (A-style) or as cards (B-style), rendered by existing PlotRenderer
  3. Phase 3 — Local model + data routing: add LocalChatProvider, data-sharing toggle in settings, routing logic

Pros

  • Shippable incrementally
  • Each phase is testable
  • Lower risk

Cons

  • 3 implementation cycles
B

Big Bang

One spec covering everything: redesigned ChatPanel, viz rendering, local model routing, data-sharing setting, all at once.

Pros

  • Consistent design from day 1
  • No intermediate states

Cons

  • Large single PR
  • Hard to test mid-way
  • Riskier
C

Viz-first

Skip the visual refresh for now. Focus only on the two high-value missing features: viz-in-chat + local model routing. Polish comes later.

Pros

  • Fastest path to useful features
  • Tight scope

Cons

  • Still looks rough while you're using it
  • Visual debt to pay later
