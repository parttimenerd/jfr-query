Design: Data Flow & Key Decisions

The non-obvious wiring between streams. Let me know if anything looks wrong.

Stream 1 — How hover and lint connect to the editor

CodeMirror 6 extensions are registered once in the plot editor factory. The new plotHoverExtension is a hoverTooltip() provider — it receives the token under the cursor and does a keyed lookup in plotClauseDocs. The lint extension already runs on every parse; we extend it with a levenshtein-distance "did you mean" pass against the known shape and clause name lists. No network calls — everything is local and synchronous.

Data: plotClauseDocs.ts → hover tooltip DOM. Known shape/clause lists → lint diagnostics.

Stream 2 — Test connection ping

AiService.pingProvider() sends a single-token completion request ("hello") to the configured endpoint and measures round-trip time. The Settings tab shows a spinner while pending, then ✓ green / ✗ red with the error message or latency. Result is not cached — each button press re-tests. This avoids stale "connected" indicators after network changes.

No new state context. Result held in local component state inside SettingsPanel.

Stream 3 — "Fix with AI" trigger point

When PlotRenderer catches a render error, it already renders an error message div. We add a "Fix with AI" button there. On click it calls inlineChatRef.open({ prefill: ... }) — the same mechanism used by the existing "Ask AI" shortcut — with the current cell DSL and error text pre-filled. No new state paths; reuses the existing InlineChat open API.

For explainCell and suggestPlot: both are registered in AiService's tool registry alongside existing tools (describeTable, runQuery, etc.). They follow the exact same tool-call/response pattern — no architectural change, just two new entries.

Column-name validation: post-process ghost-text completions — strip suggestions where an identifier token doesn't appear in cellResultSchema.columns. Applied client-side, no model round-trip.

Stream 4 — Onboarding cell lifecycle

On notebook load, App.tsx checks: cells.length === 0 && !localStorage.getItem('jfrq:onboarding-dismissed'). If true, it prepends a synthetic TemplatedMarkdown cell flagged as isOnboarding: true. The cell renders a "Getting started" panel with a dismiss button. On dismiss: set localStorage key + remove the cell. The cell is never persisted to the notebook file — it's ephemeral UI state only.

No new context. Flag lives on the cell object, cleared on dismiss.

Stream 4 — PlotHelpModal search + Insert example

Search is client-side: a single filterTerm state string, matched against shape names, clause names, and description text. "Insert example" calls editorRef.dispatch(insertText(example.code)) — the same mechanism used by autocomplete snippet insertion. Requires the modal to receive the active editor ref, which it already does via NotebookCell context.
