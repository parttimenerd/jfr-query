A — Contextual help in the editor

How should we surface help while typing? Pick the approach you prefer.

A

Hover docs only (minimal)

Extend the existing CodeMirror hover provider: show clause signatures and descriptions when hovering over any plot keyword (BRUSH, LINK_X, AXIS_Y, etc.). Uses the plotClauseDocs.ts data already in place. No new UI surfaces.

Pros

  • Very low complexity
  • Already half-done (SQL hover exists)
  • Non-intrusive

Cons

  • No error guidance
  • User must hover to discover
B

Hover docs + inline error hints ★ recommended

Hover docs (A) plus: when a plot cell has a parse error, show a CodeMirror diagnostic with a short "fix suggestion" tooltip at the error location. E.g. unknown shape line_chart → "Did you mean LINE_CHART?"

Pros

  • Fixes the most painful UX gap (silent parse failures)
  • Reuses existing lint infrastructure
  • Discoverable without opening Help

Cons

  • Requires small linter extension
C

Full inline help panel

A collapsible side-panel inside each plot cell showing the relevant clause doc for whatever keyword the cursor is on — updates as you type. Think "mini PlotHelpModal" always open beside the editor.

Pros

  • Most discoverable
  • No hover required

Cons

  • Takes up significant vertical space
  • High implementation complexity
  • Duplicates PlotHelpModal
